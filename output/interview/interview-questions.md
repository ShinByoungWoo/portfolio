## 1. 경력·기여·지원 동기

### Q01. ★ 1분 정도로 본인을 소개해 주세요.

**꼬리질문:** 게임 개발자가 아니라 프론트엔드 개발자라고 소개하는 이유는 무엇인가요?

### Q02. ★ 본인의 강점을 가장 잘 보여 주는 프로젝트 하나를 설명해 주세요.

**꼬리질문:** 그 프로젝트에서 사용자가 실제로 달라졌다고 느끼는 부분은 무엇인가요?

### Q03. ★ 프로젝트 전체 성과와 본인이 직접 한 일을 어떻게 구분할 수 있나요?

**꼬리질문:** 프론트엔드 인원, 백엔드 담당, 본인의 설계·구현 범위를 구체적으로 설명할 수 있나요?

### Q04. ★ 900개 교육기관, 96개 콘텐츠 유형, 2,128개 파일은 어떤 의미의 수치인가요?

**꼬리질문:** 그 숫자가 본인의 성과라는 것을 어떻게 입증하나요? 개선 전후 수치는 없나요?

### Q05. 프로젝트 기간이 겹치는데, 동시에 어떤 일을 한 것인가요?

**꼬리질문:** 신규 개발과 유지보수 요청이 겹치면 우선순위를 어떻게 정했나요?

### Q06. ★ Vue/Nuxt가 주력인데 React를 사용하는 팀에도 기여할 수 있나요?

**꼬리질문:** React로 만든 개인 포트폴리오와 React 제품 개발 경험은 어떻게 다르다고 생각하나요?

### Q07. 비전공자로 개발을 시작한 계기와 부족한 기본기를 보완한 방법을 설명해 주세요.

**꼬리질문:** 방송통신대학교 학습이 실제 개발에 도움이 된 사례가 있나요?

### Q08. 이직하려는 이유와 다음 회사에서 하고 싶은 일을 설명해 주세요.

**꼬리질문:** 우리 회사의 어떤 문제를 본인의 경험으로 해결할 수 있다고 생각하나요?

## 2. Codmos Partner Web

### Q09. ★ 파트너마다 화면을 복제하지 않고 동적 라우팅을 사용한 이유는 무엇인가요?

**꼬리질문:** 모든 파트너를 같은 URL 구조와 같은 진입 흐름으로 만들었나요?

### Q10. partnerKey와 contentSlug는 어디서 검증하며, 검증이 실패하면 어떻게 처리하나요?

**꼬리질문:** 올바른 형식의 URL이면 해당 콘텐츠에 접근해도 된다는 뜻인가요?

### Q11. ★ 신규 시작, 이어하기, 세션 만료 후 재방문 흐름을 설명해 주세요.

**꼬리질문:** ‘이어하기’는 항상 마지막 미션으로 보내나요? ‘새로하기’에서는 무엇을 초기화하나요?

### Q12. 서버, Pinia 또는 Nuxt state, cookie, localStorage에는 각각 어떤 상태를 두나요?

**꼬리질문:** 다른 파트너로 전환하거나 저장된 사용자 정보가 오래됐을 때 어떻게 하나요?

### Q13. 콘텐츠를 직접 컴포넌트로 넣지 않고 iframe으로 실행한 이유는 무엇인가요?

**꼬리질문:** iframe 구조 때문에 추가로 해결해야 하는 UX·운영 문제는 무엇인가요?

### Q14. ★ postMessage 통신에서 무엇을 검증해야 하나요?

**꼬리질문:** origin만 확인하면 충분한가요? targetOrigin에 `*`를 쓰면 어떤 문제가 있나요?

### Q15. iframe에서 준비·완료 메시지가 늦게 오거나 중복해서 오면 어떻게 처리하나요?

**꼬리질문:** 프론트에서 중복 메시지를 걸러 주면 학습 기록의 중복 저장도 완전히 막을 수 있나요?

### Q16. 미션 화면에서 로딩, 빈 데이터, 네트워크 오류, 세션 만료를 어떻게 구분하나요?

**꼬리질문:** ‘다시 시도’ 버튼을 누르면 iframe만 새로고침하면 되나요?

### Q17. 로그인 또는 세션 복구 후 돌아갈 경로를 저장할 때 무엇을 주의하나요?

**꼬리질문:** redirectTo가 `/`로 시작하는지만 검사하면 안전한가요?

### Q18. Nuxt에서 iframe, window, localStorage를 사용할 때 주의할 점은 무엇인가요?

**꼬리질문:** Nuxt를 사용하면 반드시 SSR인가요? hydration mismatch는 왜 발생하나요?

## 3. Codmos CMS·콘텐츠 배포

### Q19. ★ Vue 2·Vue 3·Nuxt·정적 HTML 콘텐츠를 어떻게 같은 배포 흐름으로 관리했나요?

**꼬리질문:** 빌드 산출물이 정적 파일이 아니라 서버 실행을 요구한다면 어떻게 하나요?

### Q20. npm Workspaces를 사용한 이유와 한계를 설명해 주세요.

**꼬리질문:** Workspaces를 사용했다는 이유만으로 마이크로 프론트엔드라고 할 수 있나요?

### Q21. ★ 서비스와 콘텐츠의 ‘독립 배포’가 가능해진 구조를 설명해 주세요.

**꼬리질문:** 콘텐츠에서 보내는 메시지 형식이 바뀌어도 서비스 배포가 필요 없나요?

### Q22. 같은 콘텐츠 버전의 중복 배포와 배포 중 일부 파일만 올라간 상태를 어떻게 다루나요?

**꼬리질문:** 업로드 전에 같은 버전이 있는지 한 번 확인하면 동시 배포까지 막을 수 있나요?

### Q23. CDN을 사용하는데 배포 후에도 이전 화면이 보이면 무엇부터 확인하나요?

**꼬리질문:** `no-cache`, `no-store`, 버전 URL은 각각 언제 사용하나요?

### Q24. ★ 콘텐츠 롤백은 어떻게 동작하며 무엇까지 되돌릴 수 있나요?

**꼬리질문:** 이전 파일로 되돌렸는데도 서비스가 복구되지 않을 수 있는 이유는 무엇인가요?

### Q25. 콘텐츠 메타데이터에는 무엇을 넣고 어디에서 검증하나요?

**꼬리질문:** 예전 콘텐츠와 새 콘텐츠의 메타데이터 형식이 다르면 어떻게 공존시키나요?

### Q26. 콘텐츠 이름이나 업로드 경로를 파일 경로로 사용할 때 무엇을 검증해야 하나요?

**꼬리질문:** 입력에서 `../`만 제거하면 경로 이탈을 막을 수 있나요?

### Q27. Puppeteer로 HTML 리소스를 수집하고 CDN 경로로 바꾸는 과정을 설명해 주세요.

**꼬리질문:** 지연 로딩 이미지, CSS 내부 URL, 다운로드 실패는 어떻게 처리하나요?

### Q28. 이미지 URL 만료와 base64 용량 문제를 어떻게 해결했나요?

**꼬리질문:** base64를 쓰면 파일 크기가 얼마나 달라지며, 모든 리소스를 외부 파일로 빼는 것이 유리한가요?

**꼬리질문:** 새로고침이나 뒤로가기를 해도 같은 목록을 보여 주려면 어떻게 하나요?

### Q33. 목록의 초기 상태, 로딩, 빈 결과, 실패 상태를 어떻게 설계하나요?

### Q35. ★ duration과 timeSpent를 구분한 이유는 무엇인가요?

**꼬리질문:** 학습 화면을 켜 둔 시간, 실제 활동 시간, 반복 학습 시간은 어떻게 집계해야 하나요?

## 5. 인증·암호화·보안

**꼬리질문:** Web Crypto API를 사용할 수 없을 때 원문을 반환하는 구현은 괜찮은가요?
