## 현재 문구에서 제외하거나 수정한 내용

- 사용자 요청에 따라 AES-GCM·Web Crypto API 및 암호화 기여 표현 제거.
- LMS·Admin을 분리해 프론트엔드 3명 중 담당 화면과 API 연동 범위 명시.
- AI 리포트는 모델 개발·지표 설계가 아닌 결과 조회·표시·상태 관리 중심으로 정리.
- 기존 2024년 HTML 자동화 항목은 이번에 확인한 2026년 CMS·Canva 등록 작업으로 교정. 별도의 2024년 작업이 있었다면 분리해서 추가 확인할 것.
- CMS 전체 아키텍처와 S3/CDN 시스템을 혼자 구축했다는 표현을 사용하지 않음.
- 라우트 가드를 서버 API의 보안 검증이나 Path Traversal 방어 전체로 표현하지 않음.
- React는 현재 개인 포트폴리오 경험, Vue·Nuxt·Pinia는 주력 실무로 구분.

## 추가 확인 후 보강할 증거

1. 기존 이력서의 Canvas 40→60 FPS: 측정 기기·브라우저·장면·측정 방식 확인. 이번에는 재측정하지 않았으며 기존 기재를 유지했다.
2. 기존 Spark EDU·CSAP 대응: 실제 담당 범위와 검증 결과 확인. 이번 세 레포 조사로 이 과거 경험까지 검증한 것은 아니다.
3. 회사 소개의 900개 교육기관: 기준 시점·공개 출처 확인. 개인 담당 기능의 사용자 수로 쓰지 않는다.
4. 코스·리포트와 Admin의 익명화 시연을 추가하면 일반 서비스 개발의 증거를 보강할 수 있다.
5. CMS에 2026-05-26 성능 분석 보고서가 존재한다. 원본 측정 환경·작성자·재현성을 확인하기 전 수치를 개인 성과로 쓰지 않는다.

## 지금부터 확보할 수 있는 정량 자료

- Admin: 동일 데이터에서 목록 조회 응답 크기·표시 건수·검색 요청 수 비교. 설정값(100개 청크)을 성능 향상률로 바꾸지 않는다.
- CMS: 동일 콘텐츠를 수동 등록하는 절차와 스크립트 처리 시간, 이미지 가공 전후 바이트 수 비교. 단순 HTML 크기와 전체 네트워크 전송량을 구분한다.
- LMS: 단원 변경·새로고침·늦은 수업 입장 등 재현 시나리오와 수정 전후 결과를 기록한다.
- QA·CS: 반복 문의의 재현 조건, 원인, 수정 내용, 검증 결과를 하나의 사례로 작성한다. 근거 없는 오류 감소율은 넣지 않는다.
