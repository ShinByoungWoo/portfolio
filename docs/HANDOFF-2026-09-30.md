## 여기서 나눈 대화

### 1. CMS 이미지 최적화 성과를 숫자로 정리

사용자는 CMS 자동화 파이프라인에서 이미지 다운로드 후 중복 제거, WebP 변환으로 콘텐츠 폴더 용량이 60% 이상 줄었다고 기억했습니다. 추정만 쓰지 않고 `codmos-cms`의 Canva 콘텐츠를 근거로 정리하기로 했습니다.

조사한 구현은 `C:\workspace\codmos-cms\scripts\process-canva.mjs`입니다. 이미지 원본 바이트의 MD5 앞 12자리를 파일명으로 사용하고, 래스터 이미지를 `sharp`의 WebP quality 85로 변환합니다. SVG·GIF는 유지하며 변환 실패 시 원본을 저장합니다.

2026.09.23 집계 결과는 다음과 같습니다. 이번 9월 30일에 재측정한 값은 아닙니다.

| 항목 | 값 |
| --- | ---: |
| 비어 있지 않은 `canva_*` 콘텐츠 폴더 | 10개 |
| HTML 문서 | 208개 |
| 현재 public 전체 파일 | 501.28 MiB |
| 저장된 해시 이름 이미지 전체 | 433.78 MiB |
| HTML에서 참조된 고유 이미지 | 419.41 MiB |
| 현재 형식으로 페이지마다 따로 저장하는 가정 | 1,128.21 MiB |
| 비교 가정 대비 차이 | 708.80 MiB / 약 62.8% |

**62.8%는 현재 이미지 형식을 유지한 페이지별 중복 저장 가정과의 비교 추산입니다.** WebP 변환 전 원본 용량이 없어 압축과 중복 제거 전의 실제 총량은 복원하지 못했습니다. 폴더마다 60% 이상 줄었다는 뜻도 아닙니다. 로딩 속도나 CDN 요금 감소율로 바꿔 쓰면 안 됩니다.

산출식, 제외 대상, 이미지 참조 검사 한계는 [cms-image-metrics.md](cms-image-metrics.md)에 있습니다. 초기 등록 샘플의 15개 언어별 산출물·253개 WebP 이미지와 이번 10개 폴더·208개 HTML은 서로 다른 집계 범위입니다.

### 2. 친근한 이력서와 회사별 맞춤 지원

사용자의 방향은 회사마다 일부 내용을 수정해 지원하고, 딱딱한 이력서를 가벼운 농담이 섞인 친근한 문장으로 바꾸는 것입니다.

제안한 방법은 소개 2~3문장, 프로젝트 순서, 지원 직무와 연결되는 핵심 성과 2~3개를 회사별로 조정하는 것입니다. 성과와 기술 설명은 구체적으로 유지하고 소개에 말투를 담는 방향입니다. 아래 소개는 제안 초안이며 전체 이력서에 확정 적용한 문구가 아닙니다.

> 안녕하세요. 학생과 교사가 쓰는 화면부터, 그 화면에 올라갈 콘텐츠의 배포까지 만들어 온 프론트엔드 개발자 신병우입니다. Vue/Nuxt로 사용자 서비스와 운영 도구를 개발했습니다. 반복 작업은 코드에게 양보하는 편이라, 콘텐츠 등록·배포 자동화도 직접 만들었습니다.

아직 지원 회사나 채용 공고는 정하지 않았습니다. 다음에는 공고 하나를 기준으로 첫 맞춤 버전을 만들면 됩니다.
